# Card contract (frozen in 5a)

The interface between the card engine (Python, Person A) and the card renderers (React, Person B).
**Source of truth:** [`agent/buddy/cards/schema.py`](../../agent/buddy/cards/schema.py). Change it only together, and update this page.

## Tool the agent calls: `compare_suppliers`
The agent extracts these fields; code decides everything else (plan 05).

| Field | Type | Notes |
|---|---|---|
| `request` | string | The buyer's message, verbatim. Supplier IDs are taken from it by regex |
| `intent` | `compare` \| `overview` \| `watchlist` \| `exposure` \| `choose` | `compare` with no mentions becomes `overview` (code) |
| `direction` | `safest` \| `watch` | |
| `mentions` | list of `{phrase, metrics: [MetricKey]}` | More than one candidate that the buyer didn't each name → **the buyer chooses one**. A clear cue word in `request` ("bankrupt", "credit rating", "on time", …) narrows the candidates or fills in a missing metric (code, `CLEAR_CUES`) |
| `supplier_ids` | list of `SUPP_\d{5}` | Kept only if present in `request` |
| `use_compare_tray`, `rank_by`, `rank_order`, `limit` | | Supplier selection when no IDs are given (2–20) |

**Returns** `ToolResult`, one of:
- `status: "ok"` with a `card` and a `summary`
- `status: "needs_clarification"` with a `question` and `options`
- `status: "error"` with a `message`

## Card (what the renderers receive)

| Field | Meaning |
|---|---|
| `cardId` | Stable hash of template + metrics + suppliers |
| `renderer` | `rank` \| `scatter` \| `table`, which decides the React component |
| `template` | Spec template id (e.g. `financial_credit_card`), which picks the renderer's variant |
| `title`, `summary` | Display text. `summary` is written by code from `facts` |
| `intent`, `direction` | As above |
| `metrics`, `metricLabels`, `valueDirection` | Which metrics, their display names, and whether lower or higher is better (or exposure, or categorical) |
| `sort` | `{field, direction: asc \| desc}` |
| `dataShape` | `{flags, scale, fallbackApplied, notes}`. Show the `notes` on the card |
| `referenceBands` | Risk colours: **Low 0–24, Medium 25–49, High 50–74, Critical 75–100** (the same for every score) |
| `quadrants` | Scatter only: `{x, y, xThreshold, yThreshold, labels, goodZone}` |
| `suppliers[]` | `{supplierID, supplierName, values, levels, flags}`. The flags include `best`, `worst`, `hidden_watchout` and `outlier` |
| `facts` | What `summary` is based on (best, worst, spread, …) |

**Scales:**
- `fixed_0_100` is the default for risk scores.
- `log` is always used for spend.
- `linear` is used for the percentage metrics.
- `zoomed` is only used with a visible note.
- `categorical` is used for sourcing and complexity.

**Pixel-level decisions are the renderer's job,** because only it knows the screen geometry: overlap, jitter, label offsets, zoom insets.
